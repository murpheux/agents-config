1. Summary

Upstream Aider has a single agent loop. It has no subagents, hooks, MCP or custom slash commands; the cecli fork adds them. The OpenCode design was mapped onto Aider's native levers:

  • model tiers: main, weak (commit messages and history summaries), editor, and architect mode;
  • aliases and wrappers as the router;
  • /load command files as workflows;
  • read-only skill files loaded on demand;
  • Aider's own safety options.

The most important security fix: Aider commits with --no-verify by default, which silently skips the ggshield pre-commit hook. This config turns verification on.

5. Cost levers

  • cache-prompts caches the system prompt, conventions and repo map, and requires cache_control per model.
  • cache-keepalive-pings: 0, because pings cost money.
  • map-tokens: 1024 and max-chat-history-tokens: 6000; old turns are summarised by the weak model.
  • auto-test: false, because failing output is re-sent up to 3 times; the per-repo test-cmd examples pipe through tail.
  • Reasoning effort only reaches the main model; max_tokens caps are set per model; aliases pick the cheapest tier.
  • Aider never enforces budgets, so put spend limits on the LiteLLM virtual key.

6. Security

  • Commits: git-commit-verify: true runs ggshield and other hooks; dirty-commits: false never sweeps in your uncommitted work; signing follows commit.gpgsign.
  • Shell: suggest-shell-commands: false, yes-always: false — nothing runs unless you type /run or confirm.
  • Context:
    • detect-urls: false keeps untrusted web content out;
    • add-gitignore-files: false;
    • the .aiderignore template covers env files, keys, state, kube/cloud configs;
    • gitignore: false stops Aider editing each repo's .gitignore.
  • Credentials: injected per process by op run. The reference file is not named ~/.env, because Aider auto-loads that with override and would replace the real keys with op:// literals.
  • TLS: verify-ssl: true, with SSL_CERT_FILE/REQUESTS_CA_BUNDLE pointing at the full OS bundle, not at the home-lab CA alone.

7. Gotchas handled

  • Lists never merge: a repo-level read: replaces the global one, so the README shows repeating it.
  • Paths: ~ expands only in read, so settings and metadata paths are absolute, rendered per machine by the installer.
  • Lint keys: lint-cmd entries are quoted with grep-ast language keys (csharp, hcl, powershell, bash, dockerfile).
  • OpenRouter OAuth: Aider would store the key in plain text; the aliases supply OPENROUTER_API_KEY so this never triggers.
  • Untrusted repos: their .aider.conf.yml/.env can set commands or the API base — inspect them first.

8. Validation

YAML and json5 files parse. The installer smoke test showed the config rendering with absolute paths for the temp HOME, 20 skills and 24 loaders installed, and aider.op.env at mode 0600. The conventions file retains all 277 checked items. Aider isn't installed here, so there was no live run.
