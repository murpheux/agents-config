1. Summary

The Copilot CLI has everything the design needs:

  • custom agents with tool restrictions, so the router literally cannot edit or run shell;
  • per-subagent model and effort tiers (subagents.agents);
  • personal instructions and skills;
  • fail-closed preToolUse hooks;
  • a sandbox, and optional managed deny/ask/allow rules.

Because ~/.copilot is also read by VS Code, instructions, skills and hooks are identical to the vscode/ folder. Agents are target-scoped (github-copilot) so VS Code doesn't list them.

5. Cost levers

  • A cheap router, plus cheap built-in explore/task/code-review, so the most frequent helper calls don't run on the default model.
  • AI-credit visibility in the footer; /usage and /context; cop-cap sets --max-ai-credits (a soft cap, minimum 30).
  • continueOnAutoMode: false: no silent model switches.
  • Autopilot is still capped by --max-autopilot-continues (default 5).

6. Guardrails

  1. Tool restriction: the router has no edit or execute tools.
  2. Guard hook: the shared 33 command rules and 18 protected paths. The CLI treats hook crashes and non-zero exits as a deny (fail closed); timeouts fail open.
  3. Sandbox (macOS/Linux): ~/.ssh, ~/.aws, ~/.gnupg, ~/.config/op, kube/docker configs and AI-tool credential files are denied. On Windows the installer drops deniedPaths, because that backend rejects them.
  4. Secrets: --secret-env-vars strips and redacts gateway, API and cloud tokens; deniedUrls blocks paste and webhook exfiltration hosts.
  5. No bypass: allow-all flags are refused, and remote: off keeps sessions local.
  6. Managed policy (optional): real deny/ask/allow rules. Note that once any list is set, unmatched operations ask, which is why reads and read-only commands are allow-listed.

8. Gotchas handled

  • User-level settings.json has no allow/deny arrays; only managed settings do. So persistent denial relies on hooks, the sandbox, aliases and the optional managed file.
  • User settings moved from config.json to settings.json (JSONC). The installer merges rather than overwriting.
  • ~/.agents/skills (Codex) is also read by the CLI, so the installer skips identical duplicates.
  • --deny-tool shell(…) matches first-level subcommands only for git/gh; everything else is covered by the hook.

9. Validation

Configs parse. The guard's 70 self-tests passed, including CLI payloads (toolName/toolArgs) with deny → exit 2. The installer smoke test merged settings while keeping an existing key (theme) and installed 8 agents, 33 skills and the hook. Both .ps1 scripts parse cleanly.
