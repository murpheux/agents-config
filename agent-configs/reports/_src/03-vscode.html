Folder: ~/agent-configs/vscode/ → <profile>/ (settings, mcp.json, prompts) and ~/.copilot/ (shared core)

1. Summary

VS Code 1.139 runs two agent harnesses:

  • Local reads profile settings, prompt files and mcp.json. It is slated for removal.
  • Copilot reads only ~/.copilot and ~/.claude.

The configuration therefore splits in two. The shared ~/.copilot core (instructions, skills, guard hook, MCP) works in both harnesses and the CLI. VS Code-only pieces go in the profile: approvals, sandbox, prompt files and mcp.json.

The router design had to adapt to one VS Code rule: a subagent priced above its caller is refused. The Router sits on the Medium tier and runs cheaper or equal-tier subagents. The premium Architect and Security run as handoff buttons, which you confirm.

5. Guardrails

  1. Terminal auto-approve: only read-only and validation commands run automatically. Push, IaC apply/destroy, cluster mutations, cloud CLIs and .ps1 always ask. Workspace npm scripts are no longer auto-approved.
  2. Guard hook: this is what actually blocks. Terminal rules only ask, and VS Code's docs say they are not a security boundary.
  3. Edit protection: .env*, state and key files, workflows and .ssh always ask. VS Code already protects .git/**, lockfiles and .vscode/*.json.
  4. Sandbox: on for macOS/Linux/WSL2 (WSL2 needs bubblewrap and socat); off on Windows, where it is experimental.
  5. Prompt injection: web fetch is not eligible for auto-approval; chat.useClaudeMdFile is off to avoid duplicated or unexpected instructions.

7. Gotchas handled

  • Prompt files don't run in the Copilot harness, so every command also exists as a skill (in the CLI folder).
  • ~/.copilot doesn't settings-sync, and on Windows + WSL each harness reads its own host. Run install.ps1 on Windows and install.sh in WSL.
  • Profile MCP servers run on Windows even in WSL windows. The Mermaid renderer tool is Local-only.
  • Agents from ~/.claude/agents also appear in the Copilot harness if Claude Code is installed; see the final report's coexistence notes.

8. Validation

The settings fragment (JSONC), mcp.json, all agents and all prompt frontmatter parse. The installer smoke test merged settings while keeping an existing key (editor.fontSize), installed 16 prompt files and mcp.json, and confirmed all 8 agents are target: vscode. install.ps1 parses cleanly.
