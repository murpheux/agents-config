1. Summary

Codex 0.157 natively provides everything the design needs:

  • custom subagents (~/.codex/agents/*.toml);
  • profiles as separate files;
  • skills;
  • stable hooks using the same JSON contract as the shared guard;
  • Starlark exec-policy rules;
  • an OS sandbox;
  • shell-environment secret filtering.

Custom prompts were removed in 0.118, so the 16 slash commands ship as explicit-only workflow skills ($review, $plan, …) in the Codex-only ~/.codex/skills.

Cached input is 10× cheaper, which is why AGENTS.md is kept as a stable prefix. web_search = "cached" is cheaper, and a smaller injection surface, than live search.

5. Guardrails (defence in depth)

  1. Sandbox: workspace-write with network off by default (the sre agent enables network). .git, .codex and .agents stay read-only.
  2. Exec policy:
    • forbidden: disk wipes, root/home deletes, force-push and history rewrites, destroy, bucket deletion, secret printing.
    • prompt: push, apply/import/state, cluster/swarm/helm mutations, opaque bash -c and PowerShell scripts, ansible-playbook.
  3. Guard hook: catches what argv prefixes miss (git push origin -f, pipes into interpreters, .env, interactive programs, patches touching secret files).
  4. Environment filtering: the built-in *KEY*/*SECRET*/*TOKEN* excludes plus 1Password, PAT, gateway, OpenRouter and AWS secret variables.
  5. Credentials: the gateway token comes from op read run by Codex itself, so it never enters model context.

7. Gotchas handled

  • Removed or changed in 2026:
    • prompts removed → workflow skills;
    • a top-level profile = is now an error → profile files;
    • approval_policy="untrusted" and wire_api="chat" are hard errors, so neither is used.
  • Silent failures:
    • unknown keys are ignored unless you run codex --strict-config (it's in the next steps);
    • untrusted repos load no AGENTS.md;
    • the default 32 KiB instructions cap would truncate AGENTS.md, so it was raised.
  • Hooks must be trusted once in /hooks.
  • Rules are prefix-only, so the hook covers reordered flags. Skill trees are CRLF-normalised, because CRLF breaks shebangs.

8. Validation

All 12 TOML files parse. The 37 rules were executed with stubs and every match/not_match example was verified. The guard handles argv arrays and apply_patch payloads (70 self-tests). The installer smoke test confirmed the hook command points at the installed guard, 20 + 16 skills are in place, and the hook exits 2 on a force-push.
